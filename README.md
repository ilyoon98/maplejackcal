# 메이플 계산기 모음

## 썬데이 메이플 공지

공통 내비게이션이 있는 페이지는 브라우저에 등록한 넥슨 Open API 키로 매주 금요일 오전 10시 30분(KST)에 `진행 중 이벤트 목록 조회`를 확인합니다. 해당 주의 `썬데이 메이플`이 있으면 금요일 오전 10시 30분부터 일요일 오후 11시 59분 59초까지 공식 이미지를 사이트 내부 팝업으로 자동 표시하고 이후 즉시 숨깁니다. 팝업의 `오늘 하루 안 보기`는 한국 날짜가 바뀔 때까지 유지됩니다. 오른쪽 아래 공지 버튼을 누르면 넥슨 공식 이벤트 페이지를 새 탭으로 엽니다. 조회 결과는 주차별로 `localStorage`에 보관하며, 공지가 아직 없거나 조회에 실패하면 30분 뒤 재시도합니다.

## 재사용할 사용자 제공 DB

새 계산기나 기능을 만들 때 [사용자 제공 DB 안내](references/maple-db/README.md)를 먼저 참고합니다. 공유 드라이브의 원본 13개 파일은 `references/maple-db/original/`에 보관했고, 출처·수정 시각·검증 해시는 `references/maple-db/sources.json`에 기록했습니다. 가격을 보정한 보스 DB는 루트의 `boss_db.json`입니다. 결정석 가격은 기존 계산기 값을 우선하며, 참고 원본의 가격으로 되돌리지 않습니다.

## 스타포스 로그

상단 한 장의 요약 카드에 **총 사용 메소와 종합 손익**을 나란히 표시합니다. 현재 조회 범위, 강화·파괴 횟수와 필요한 경우에만 일부 추정·일부 비교 표시를 남겼습니다. 강화비·입력한 대체 장비비·계정 전체 합계, 금액·계산 건수·누락 사유와 계산 설명은 기본으로 접힌 **계산 상세**에서 확인합니다. 장비별 카드도 장비명·서버·캐릭터와 사용 메소·손익만 표시하며, 레벨·별 변화·성공/실패/파괴·기간·구간 후보는 클릭한 상세창에서 확인합니다. 현재 단가 환산이므로 과거 실제 지출 및 복구 메소는 복원하지 않습니다. 금액은 억·만 단위로 표시하고 만 미만은 생략합니다. 계산 및 저장에는 원래 값을 유지하며, 0이 아닌 1만 미만 금액은 ‘1만 미만’으로 표시합니다.

API 키가 등록되어 있으면 페이지 입장과 키 변경 시 최근 2년 기록을 자동 조회합니다. 저장된 기록과 비용 설정을 먼저 표시하고, 비어 있거나 갱신이 필요한 날짜만 API로 확인합니다. 확정된 과거 날짜는 30일 이후에도 재사용하며 오늘·어제는 5분 캐시를 적용합니다. 조회 중에도 기존 요약과 장비 상세를 볼 수 있고 최신 날짜 조회가 실패해도 저장된 기록을 유지합니다. 첫 전체 조회가 중단되면 다음 입장에서 완료한 날짜를 건너뛰고 이어갑니다. 날짜별 요청은 최소 300ms 간격이므로 첫 조회는 수 분 걸릴 수 있습니다. 장비 상세에서 레벨·MVP·PC방·파괴 1회 대체 장비값을 수정하고 **비용 수정 반영**을 누르면 같은 이름 장비의 전체 기록과 상단 합계에 적용합니다. 설정은 키 원문 대신 SHA-256 해시로 구분한 IndexedDB에 저장해 새로고침 후 조회해도 유지합니다. 저장된 기록과 비용 설정을 보호하기 위해 화면에 캐시 삭제 기능은 제공하지 않습니다.

장비 상세의 **연속 강화 구간 선택**은 별 흐름 단절·이벤트 변경·스타캐치 및 같은 별에서의 파괴방지 변경을 기준으로 후보를 제공합니다. 장비 고유 ID가 없어 동일 장비 여부를 확정하지 않으므로 사용자가 확인해야 합니다. 구간 선택은 목표 분석만 바꾸며 상단 합계에서 다른 기록을 제외하지 않습니다. [2026-03-19 공식 업데이트](https://maplestory.nexon.com/news/update/799)부터 스타캐치 보정이 상시 적용되고 API의 `starcatch_result`가 `null`로 반환됩니다. 해당 날짜 이후의 명시적 `null` 기록은 정상 보정 확률로 종합·시도별 손익과 목표 분석에 포함하며 상세 표에 자동 적용으로 표시합니다. 시도별 손익은 명시적인 스타캐치 실패·미적용도 기본 확률로 계산합니다. 개편 이전의 `null`과 필드 누락은 적용 여부를 가정하지 않고 제외합니다. 손익 제외 사유·건수는 계산 상세 및 장비 상세 상단에 표시하고 카드 금액의 툴팁에서도 확인합니다. 비교 가능한 기록이 없을 때 총합 금액은 0 대신 `—`로 표시합니다. 선택 구간의 목표 달성 분석은 기존 스타캐치 성공 조건을 유지합니다.

장비 사전 원본은 `equipment_data.json`입니다. 기존 60종에 사용자 지정 장신구·하트 13종, 블랙 방어구 3종, 아케인셰이드 방어구 30종을 추가해 개별 항목 106종을 등록했습니다. 마이스터 링·트와일라이트 마크·분노한 자쿰의 벨트·블랙빈 마크·데이브레이크 펜던트·가디언 엔젤 링 2종·메커네이터 펜던트·플라즈마 하트·페어리 하트·에스텔라 이어링·도미네이터 펜던트·골든 클로버 벨트는 사용자가 지정한 레벨과 부위를 사용합니다. 메이지로브는 아케인셰이드 메이지슈트의 별칭이며, 슈트·슈즈·케이프는 한벌옷·신발·망토로 분류합니다. `블랙 ` 접두사 계열은 100제로 인식하고, 개별 등록한 방어구 이외에는 무기·보조무기로 표시합니다. 사용자 지정 출처는 `user-provided:2026-10-08`로 공식 URL과 구분합니다. 전체 장비 목록은 아니며 세트 효과 수치나 실제 사용 메소는 포함하지 않습니다. 띄어쓰기 차이와 등록한 별칭은 같은 항목으로 찾되 서로 다른 장비 이름을 임의로 합치지 않습니다.

JSON 수정 후 `node tools/build-equipment-data.cjs`를 실행해 브라우저용 `equipment_data.js`도 함께 갱신합니다. `--check` 옵션으로 생성본 일치와 이름 중복을 검사합니다. 로컬 파일로 열어도 작동하도록 JSON을 fetch하지 않고 생성본을 로드합니다. 카드와 상세에는 확인된 레벨·부위·세트를 표시합니다. 사전에 없는 기존 4개 장비 계열의 레벨 추론은 유지하되 ‘이름 기준 추정’으로 구분하고, 나머지는 레벨 미확인으로 표시합니다.

공통 상단의 **로그보기** 탭에서 `starforce_history.html`로 이동합니다. 기존 `nexon_key.js`의 브라우저 API 키와 보스 수익 계산기의 `NexonCharacters.fetch`·`worldIconPath`를 재사용합니다. 캐릭터 선택 목록은 현재 조회 기간에 메소 스타포스 기록이 있는 캐릭터로만 구성합니다. `/character/list`는 일치하는 캐릭터의 레벨 정보와 서버 목록에 활용하며, 기록이 없는 계정 캐릭터나 특수 강화 재화 기록만 있는 캐릭터는 선택 목록에서 제외합니다. 조회 전에는 기록 불러오기 안내를 표시하고 목록 API가 실패해도 강화 기록의 캐릭터를 선택할 수 있습니다. 서버와 캐릭터는 체크박스로 여러 개를 선택하며, 두 조건의 교집합으로 장비 카드와 총합을 필터링합니다. 기본은 전체 선택이며 상단 전체 체크박스와 개별 항목이 모두 체크됩니다. 개별 항목을 해제하면 그 항목만 제외하고, 일부 선택 시 상단 전체 체크박스는 부분 선택 상태로 표시합니다. 상단 전체 체크박스는 전체 선택·해제를 수행하고, 전부 해제하면 선택 없음으로 표시하며 기록을 집계하지 않습니다. 같은 닉네임도 서버로 구분하며 서버를 바꿔도 기존 캐릭터 선택은 보존합니다. 기간 조회가 완료된 뒤 새 기록에 없는 캐릭터 선택은 해제하되, 부분 조회 중에는 아직 불러오지 않은 캐릭터 선택을 보존합니다. 챌린저스 1~4의 아이콘은 `챌린저스.webp`를 공유합니다. 보스 정산은 닉네임 → `/id` → OCID → 스케줄러 조회를 사용하지만, 스타포스 기록은 `/history/starforce`에 `count`, `date` 또는 `cursor`만 전달합니다. 필터 변경은 API를 다시 호출하지 않습니다.

장비 상세에서 연속 구간·목표 별·강화 조건을 확인한 뒤 **선택 구간 분석**을 누르면 최초 목표 달성까지의 환산 사용액과 기대비용 차이를 크게 표시합니다. 기대비용보다 적게 사용하면 **이득 (절약)**, 많이 사용하면 **손해 (초과)**이며 거래 손익이나 과거 실제 지출은 아닙니다. 목표 미달성은 손익을 판정하지 않고 입력이나 구간이 바뀌면 기존 판정을 지웁니다.

- Flatpickr 4.6.13 한국어 달력 레이어와 최근 7일·30일·1년·전체(최근 2년) 버튼으로 기간을 선택합니다. 달력은 입력칸 아래에 겹쳐 열려 본문을 밀지 않으며 월 이동 버튼 위치를 유지합니다. 같은 입력칸을 다시 클릭하거나 Enter·Space를 누르면 닫힙니다. 자체 달력 렌더링을 제거하고 버전 고정한 배포 파일·한국어 로케일·MIT 라이선스를 `vendor/flatpickr/`에 포함하여 CDN 없이 로드합니다. 최근 2년 이내를 KST 날짜별로 조회하고, 각 날짜의 `next_cursor`를 끝까지 처리합니다. ID 중복을 제거하고 시간순 정렬 후 월드·캐릭터·장비 이름으로 묶습니다. 조회 오류·취소 시 부분 결과를 완료된 집계로 표시하지 않습니다. 완료한 날짜는 빈 결과도 IndexedDB에 저장합니다. API 키의 SHA-256 해시로 저장 공간을 구분하며 키 원문은 기록 저장소에 넣지 않습니다. 오늘·어제는 5분 캐시, 확정된 과거 날짜는 재사용합니다. 해당 날짜가 끝나고 API 반영 지연 5분이 지나기 전에 저장한 기록은 나중에도 갱신합니다. 최근 날짜부터 조회하고, 실패한 날짜는 저장하지 않아 다음 조회 때 다시 시도합니다. 오류·취소 시 확보한 날짜만 부분 결과로 표시하며 전체 기간 합계와 구분합니다. 저장소 사용 실패 시 API 조회는 계속하고 저장 실패를 안내합니다. 브라우저·도메인이 다르면 캐시는 공유되지 않습니다.
- 1회 최대 1,000개 기록을 받으며 요청 시작 간격을 최소 300ms로 제한합니다. HTTP 429 / OPENAPI00007은 같은 페이지를 1·2·4초 대기 후 최대 3회 재시도합니다. `Retry-After`가 있으면 그보다 일찍 재시도하지 않고, 30초 초과 대기는 자동 재시도하지 않습니다. 대기 중에도 취소할 수 있습니다. 개발 단계 키의 초당 5회·하루 1,000회 요청 제한은 페이지당 기록 개수 제한과 별개이며, 다른 탭·서비스와 공유하는 할당량까지 이 화면이 제어할 수는 없습니다.
- 장비 카드의 사용 메소 옆에 해당 장비 전체 기록의 손익을 표시하고 클릭하면 상세창을 엽니다. 에테르넬·아케인셰이드·앱솔랩스·파프니르는 이름으로 레벨을 추론하며 다른 장비는 상세의 접힌 수정 항목에서 레벨을 입력합니다. 장비 고유 ID가 없어 같은 이름의 장비는 하나의 묶음이며, 시작·종료 순번은 필요한 경우에만 펼치는 고급 설정으로 제공합니다.
- 기록별 `starforce_event_list`의 적용 범위·비용 할인율 및 `destroy_defence`를 자동 적용합니다. 이벤트가 달라져도 비용은 각 시도별로 합산합니다. MVP·PC방은 기본 미적용이며 상세에서 수정할 수 있습니다. 해석할 수 없는 이벤트 범위·할인율, 특수 재화·슈페리얼 등은 비용을 계산하지 않고 누락 건수를 표시합니다. **현재 단가 환산값**이므로 과거 패치별 실제 지출을 복원하는 기능은 아닙니다. 복구 메소는 제외하며 입력한 대체 장비값은 파괴 횟수만큼 카드와 상단 합계에 반영합니다.
- 특수 강화 재화 기록은 사용 메소·대체 장비비·종합 손익·장비 카드·강화 및 파괴 횟수에서 모두 제외합니다. 재화 필터와 특수 재화 전용 장비 카드도 표시하지 않습니다. 원본 캐시는 유지하며, 숨겨진 기록을 가로질러 연속 강화 구간을 이어 붙이지 않습니다. 불필요한 장비 이름별 묶음 개수는 요약에서 제거했습니다.
- 종합 손익과 상세의 시도별 손익은 목표 별을 추정하지 않습니다. 성공은 해당 별을 한 단계 올리는 기대비용에서 그 시도 비용을 빼고, 실패·유지는 시도 비용을 뺍니다. 파괴는 12성부터 파괴 직전 별까지의 기대비용 합계와 시도 비용·입력한 대체 장비값을 뺍니다. 기대비용은 기록의 이벤트, 현재 별의 파괴방지, 사용자 입력 할인·장비값을 적용하고 다른 별의 복귀 경로는 파괴방지 미사용을 기준으로 계산합니다. 파괴 후 실제 재강화 시도는 각각 별도로 평가하며 파괴 시 미래 복구 지출을 실제 사용액에 더하지 않습니다. 모델 조건에 따른 성공·유지·파괴 점수의 확률 가중 평균은 0입니다. 계산 가능한 시도의 점수를 합산하고 이득·손해 시도 합계, 비교 건수와 제외 사유를 표시합니다. 실제 거래 손익이 아닌 현재 단가의 기대비용 대비 결과 비교입니다.
- 시도별 기대비용은 기록의 이벤트 적용 범위를 별마다 해석해 비용 할인·파괴 확률 감소·확정 성공을 적용합니다. 할인율이나 범위가 기존 계산기의 고정된 체크박스와 다르다는 이유만으로 제외하지 않습니다. 해석 불가능한 범위, 100% 이외의 성공 확률 이벤트 및 추가 별 이벤트는 제외 사유를 표시합니다. 기존 계산기의 기본 동작은 유지하고 기록별 조건을 넘겼을 때만 별별 확률·단가를 사용합니다.
- 기존 `StarforceCalc`를 재사용하고 파괴 시 12성 복귀 모델을 사용합니다. 별 복구, 슈페리얼·펄스·특수 강화, 하락/다중 성 상승과 이어지지 않는 구간은 분석을 제한합니다. 이벤트 및 강화 조건 원문은 상세 표에 표시합니다. 동일 조건 여부는 사용자가 확인해야 합니다.
- 목표 최초 달성까지의 비용을 같은 조건의 기대비용과 비교합니다. 횟수 기준 상위 확률은 성공·유지·12성 복귀의 최초 도달 분포를 동적 계획법으로 계산하며 전체 유저 순위가 아닙니다. 목표 미달성은 손익을 판정하지 않고 미달성 확률을 표시합니다. 20,000회를 넘는 구간은 확률 계산을 생략합니다. 목표 달성 후 추가 사용은 구간 비용에만 포함합니다.
- 전체 비용은 레벨과 조건을 해석할 수 있는 기록 전체를 자동 합산하고 비용 반영 건수를 표시합니다. 목표 달성 분석은 별도이며 이벤트·파괴방지 조건이 달라지거나 계산기의 이벤트 범위와 일치하지 않으면 확률 비교를 제한합니다. 큐브·잠재 재설정 로그는 후속 범위입니다.

검증: `node --test tests/starforce-history.test.cjs tests/starforce-safeguard.test.cjs`. 브라우저 검증은 Playwright가 설치된 환경에서 `node tests/starforce-history-ui.cjs`로 실행합니다. 필요 시 `PLAYWRIGHT_CHANNEL=msedge`로 설치된 Edge를 사용합니다. 브라우저 검증은 가짜 키와 모의 응답만 사용하며 실제 넥슨 API를 호출하지 않습니다.

## 잠재능력 큐브 연구소

`cube_calc.html`은 사용자가 제공한 일반·에디셔널 등급업 확률과 천장으로 기대 큐브 수, 큐브별 전략, 가상 큐브 게임을 계산합니다. 천장이 있는 경우 `기대 시도 횟수 = (1 - (1 - 성공확률)^천장) / 성공확률`을 사용하고, 천장 정보가 없는 큐브는 `1 / 성공확률`로 계산합니다. 큐브로 돌릴 때와 메소로만 재설정할 때를 항목으로 분리했습니다. 큐브는 아이템 레벨만으로 정해지는 재설정 비용(31~70: n*n*0.25 / 71~120: n*n*2.5 / 121+: n*n*20)을 모든 큐브에 같게 적용하고, 잠재능력/에디셔널 잠재능력 재설정(메소)은 레벨 구간과 현재 등급에 맞는 기존 비용표를 씁니다.

메이플스토리용 개인 계산기 모음 사이트. `index.html`이 계산기 목록(허브)이고, 계산기별로 독립된 페이지에서 동작합니다.

- **주흔 기댓값 계산기** (`trace_calc.html`) — "주흔작"(주문의 흔적을 소모하는 주문서 강화) 완성까지 기대 비용(주흔 개수·메소·시도 횟수) 계산
- **어센틱 심볼 계산기** (`authentic_symbol_calc.html`) — 그랜디스 지역 심볼 강화 비용·최소 메소 강화 경로 계산. 넥슨 오픈 API로 캐릭터 이름만 넣으면 현재 심볼 레벨을 자동 입력하고 검색 카드에 캐릭터 외형을 크게 표시. 조회에 성공한 캐릭터는 검색창 아래에 최근 검색 배지로 최대 10개까지 남아(최신순, 대소문자 구분 없이 중복 제거) 배지를 누르면 바로 다시 조회하고, 배지 오른쪽 × 로 목록에서 뺄 수 있음
- **큐브 옵션 확률** (`cube_option_calc.html`) — 잠재능력/에디셔널 탭에서 부위(무보엠·장비·장신구)와 공식 옵션표 레벨 구간을 카드로 고르고, 원하는 잠재옵션 조건(조건 하나에 옵션 최대 3개를 모두 만족 = AND, 조건은 최대 4개까지 "또는"으로 묶음 = OR)이 큐브 한 번에 뜰 확률과 기대 횟수·기대 메소·큐브 사용량(50~99%) 계산. 큐브로 돌릴 때와 메소로만 재설정할 때는 비용 체계가 달라 항목을 나눠둠 — 큐브는 아이템 레벨만으로 정해지는 재설정 비용(31~70: n*n*0.25 / 71~120: n*n*2.5 / 121+: n*n*20, 200제면 800,000), 잠재능력/에디셔널 잠재능력 재설정(메소)은 기존 레벨 구간·등급별 비용표를 그대로 사용. 아이템 레벨을 입력하면 확률 구간과 비용이 함께 맞춰짐. 수치는 최소값·세 줄 합산 기준이고 STR/DEX/INT/LUK %에는 올스탯 %를 더해 셈. 옵션표는 아래 "큐브 옵션 확률 데이터 갱신" 참고
- **아이템 제작 비용 계산기** (`item_craft_calc.html`) — 노작 구매 → 추가옵션 → 스타포스 → 잠재·에디셔널까지 한 벌을 다 맞출 때 "완전 대박이면 얼마", "평균은 얼마"를 한 번에 계산. 단계별 확률 엔진은 이미 있는 것을 그대로 씀(추가옵션 `flame_core.js`, 스타포스 `window.StarforceCalc`, 잠재·에디 `cube_core.js` + `cube_option_data.js`). 순서는 노작 → 추가옵션 → 스타포스 → 잠재로 보고, 스타포스에서 파괴되면 노작 가격 + 추가옵션 기대 비용이 다시 들어가는 것으로 계산(스타포스 계산기의 "대체 장비값"에 그 금액을 넣음). 스타포스는 샤이닝 스타포스(비용 30% 할인 + 파괴확률 30% 감소 + 5·10·15성 100%)가 기본으로 켜져 있고, **15~17성 파괴방지는 손으로 켜지 않고 노작값으로 자동 판정**함 — `StarforceCalc.breakEvenSpare`로 성마다 손익분기 노작값을 구해 파괴 1회 손실(노작 + 추가옵션 기대 비용)이 그보다 크면 켠다. 켜고 끄는 게 서로의 손익분기를 바꾸므로 더 안 바뀔 때까지 반복해서 수렴시킴. 추가옵션 · 스타포스 · 잠재 · 에디셔널에는 각각 **계산에 포함** 스위치가 있어, 이미 되어 있는 아이템을 사서 나머지만 작할 때 그 단계를 통째로 뺄 수 있음. 잠재능력 칸의 **미라클 타임** 스위치는 잠재·에디셔널 등급 상승 확률을 같이 2배로 올림(옵션이 뜰 확률과 천장은 그대로, `cube_calc.js`와 같은 규칙). 추가옵션은 **언제나 보스 장비 규칙**(옵션 4개 고정 · 3~7단계)으로 계산함 — 추가옵션을 띄울 만한 장비는 사실상 전부 보스 드롭이고, 체크박스 하나로 확률이 수백 배 갈려서 잘못 꺼두기 쉬웠다. 브라우저에 저장된 설정을 지우는 초기화 버튼이 있음. 추가옵션 목표는 주스탯 환산 급수, 잠재 목표의 주스탯 %도 STR·DEX·INT·LUK을 하나로 묶어 고름(확률이 서로 같음). 잠재 목표 수치는 세 줄 합산·올스탯 포함 최소값이라 예를 들어 24%로 적으면 9+12+올스탯3 같은 조합과 그 이상이 전부 성공으로 들어가며, 줄마다 최고 수치가 떴을 때의 합계를 옵션 줄에 같이 보여줌. 잠재·에디셔널은 메소 재설정만 쓰고(현금 큐브 값 없음) 목표 등급은 잠재능력이 유니크·레전드리, 에디셔널이 에픽·유니크·레전드리 중에 고를 수 있으며(옵션표를 모아 둔 등급까지만), 현재 등급은 잠재능력이 에픽부터(레어에서 큐브를 돌릴 일이 없음) 에디셔널이 레어부터 고를 수 있고, 등급업에 성공한 재설정이 목표 등급 옵션을 이미 한 번 굴려준 셈이라 옵션 맞추기 기대 횟수에서 1회를 뺌
- **이벤트 코인샵 계산** (`coin_shop_calc.html`) — 이벤트 코인 상점의 아이템을 장바구니에 담아 예산 안에서 뭘 살지 계획. 품목마다 살 수 있는 주차를 표시하고, 이번 주에 더 쓸 수 있는 코인과 전체 남은 코인을 나란히 보여줌. 각 품목의 "이번 주" 버튼은 이번 주 남은 코인으로 살 수 있는 만큼 담음. 이미 구매한 수량을 기록하면 남은 구매 한도와 사용 코인에 자동 반영. 현재 주차는 오늘 날짜로 자동 계산(목요일마다 전환). 상점 데이터는 `CoinShopData.xlsx`가 원본이며 아래 "이벤트 코인샵 데이터 바꾸기" 참고

## 추가옵션(환생의 불꽃) 확률

`flame_core.js`가 [넥슨 공식 확률 공개](https://maplestory.nexon.com/Guide/OtherProbability/game/gameAddOption)의 추가 옵션 규칙을 그대로 옮긴 엔진입니다. 옵션 개수 → 종류 조합 → 줄마다 단계를 전부 펼쳐서 정확한 확률을 냅니다(몬테카를로가 아님).

- 단계 설정 확률은 옵션 한 줄마다 따로 굴립니다. 검은/영원한 `[0,29,45,25,1]`, 심연 `[0,0,63,34,3]`, 타오르는/강력한 `[20,30,36,14,0]` (1~5단계, %)
- 옵션 개수는 환생의 불꽃류 공통 `[40,40,16,4]`, 보스 장비는 4개 고정
- 보스 장비는 정해진 단계에서 +2단계(3~7단계)로 취급
- 옵션 종류는 장비분류별 목록에서 균등 확률. 한 장비에 같은 종류가 두 번 붙지는 않는 것으로 봅니다
- 레벨 제한: 무기의 보스 데미지%는 90제 이상, 무기가 아닌 장비의 공격력·마력은 60제 이상, 올스탯%는 70제 이상
- 불꽃은 아이템이라 메소가 들지 않고, **추가옵션 재설정(메소)만 1회 300만 메소** 고정입니다. 확률은 공식 확률표에서 검은/영원한 환생의 불꽃과 같은 줄에 묶여 있어 동일합니다

목표는 **주스탯 환산 급수**로 겁니다(`{kind:'grade', min}`). `주스탯 1 = 1급`, `올스탯 1% = 10급`, `공격력(마력) 1 = 4급`이고, 복합 스탯은 주스탯 쪽 수치만 셉니다. STR·DEX·INT·LUK은 옵션 목록이 대칭이라 확률이 완전히 같으므로 스탯을 고를 필요가 없고, 엔진은 STR을 대표로 씁니다. 무기는 공격력·마력 수치가 무기 종류마다 달라 급수에서 뺍니다. 특정 옵션을 단계(추)로 직접 거는 조건(`{kind:'opt', id, minTier}`)도 같이 쓸 수 있습니다.

**단계별 수치 공식은 공식 페이지에 없습니다.** 커뮤니티에서 역산해 정리된 표([메이플증권 추가옵션표](https://mitemprice.kr/bonus_stat_table.php))를 따릅니다.

| 옵션 | 수치 |
| --- | --- |
| 단일 스탯 | `min(floor(lv/20)+1, 12) × 단계` |
| 이중 스탯 | `(floor(lv/40)+1) × 단계` (각각) |
| 최대 HP/MP | `min(floor(lv/10)*30, 700) × 단계` |
| 올스탯% · 이동속도 · 점프력 · 공격력 · 마력 · 보스 데미지% · 데미지% | `단계` |
| 방어력 | 130제 이하 `단계`, 140제 이상은 단일 스탯과 같은 식 |
| 착용 레벨 감소 | `-5 × 단계` |

무기의 공격력·마력만은 무기 종류마다 수치가 달라 계산기에서 **단계(추)로만** 다룹니다.

검증: `node --test tests/flame-core.test.cjs` — 같은 규칙을 직접 굴리는 몬테카를로와 대조하고, 수치 공식·레벨 제한도 확인합니다.

## 되팔기 손익 계산기

`trade_margin_calc.html` + `trade_margin_calc.js`. 경매장은 **팔 때만 판매가의 5%**를 떼고 살 때는 수수료가 없습니다. 그래서 산 가격 그대로 다시 걸면 딱 그 5%만큼 손해입니다.

- 본전 판매가 = `(개당 구매가 × 수량 + 추가 비용) ÷ (1 − 수수료율)`. 수수료가 올린 판매가에도 붙기 때문에 원가에 5%를 더하는 것과 다릅니다(700만 → 736만 8,422, 735만이 아님). 개당 가격으로 걸기 때문에 **개당 올림**합니다.
- 순이익 = `판매가 × 수량 × (1 − 수수료율) − 원가`, 수익률은 원가 기준입니다. 판매가를 넣으면 수수료·실수령·순이익을 줄줄이 보여주고, 거꾸로 "이 가격에 팔 수 있다면 얼마까지 사도 되는지"(= 실수령 − 추가 비용)도 같이 냅니다.
- 추가 비용은 큐브·스타포스처럼 산 뒤에 더 부은 메소를 총액으로 받습니다. 수수료율은 기본 5%이고 직거래용으로 0%도 고를 수 있습니다.
- 입력값은 `localStorage`의 `tradeMarginCalc` 하나에 저장됩니다. 외부 데이터·엔진 파일을 쓰지 않는 단독 페이지입니다.

## 메소마켓 시세 계산기

`meso_market_calc.html` + `meso_market_calc.js`. 메소마켓 시세는 **1억 메소당 메포**로 적히는데, 시세판에 뜬 숫자가 그대로 들어오지는 않습니다. 수수료가 어느 쪽에 붙는지에 따라 손익분기가 달라져서 수수료를 두 칸으로 나눠 받습니다.

- 실수령 시세 = `기준 시세 × (1 − 받을 때 수수료율)`. 2304에 1%면 2,280.96 메포입니다.
- 손익분기 판매 시세 = `실수령 시세 ÷ (1 − 팔 때 수수료율)`, 정수로만 걸리므로 **올림**합니다. 받을 때 1%·팔 때 0%면 2,281, 반대로 받을 때 0%·팔 때 1%면 2,328이 됩니다.
- 메포 1점당 메소 = `1억 ÷ 실수령 시세`. 목표표는 기준 실수령보다 +1 ~ +10% 더 받으려면 얼마에 걸어야 하는지를 같이 냅니다.
- 메소 수량은 억 단위(소수 가능)로 받고 전부 같은 시세에 거래된다고 봅니다. 등록해 두고 안 팔리는 시간·시세 변동·거래 한도는 계산에 없습니다.
- 입력값은 `localStorage`의 `mesoMarketCalc` 하나에 저장됩니다. 외부 데이터·엔진 파일을 쓰지 않는 단독 페이지입니다.

## 재물 비약 제작 계산기

`wealth_elixir_calc.html` + `wealth_elixir_calc.js`. 쥬니퍼베리 씨앗 → 씨앗 오일 → 소형 재물 획득의 비약 제작 사슬에서 씨앗·오일·비약 중 무엇을 사야 싼지, 만들어 팔면 얼마 남는지 계산합니다.

- 씨앗 오일 1개 평균 비용 = `(씨앗 × 6 + 최고급 허브 오일병 1,000) ÷ 0.9`. 실패 10%에도 재료가 사라져서 나눠 줍니다. 경매장 오일 값과 비교해 싼 쪽으로 비약 원가를 냅니다.
- 비약 1회(6개) 재료 원가 = `오일 × 5 + 최고급 포션 빈병 800 + 최상급 아이템 결정 × 2 + 현자의 돌`. 레시피 값은 원가에 넣지 않고 아래 최소 판매 개수로 따로 봅니다.
- 판매 실수령은 경매장 수수료 5%를 뗍니다(수수료 할인을 켜면 3%). 레시피는 사면 24시간 동안 무제한 제작이라 회차 이익과 따로 빼고, **최소 몇 개 팔아야 이득인지**를 냅니다. 재료는 6개 단위로 들어가므로 필요한 제작 횟수를 먼저 구한 뒤 그 재료값+레시피를 넘기는 판매 개수를 셉니다.
- 구매 마지노선(레시피 제외): 오일 = `(비약 시세 × 6 × (1 − 수수료) − 다른 재료) ÷ 5`, 씨앗 = 만든 오일 원가가 오일 시세나 오일 마지노선에 닿는 값 중 낮은 쪽.
- 결과 맨 위 **추천** 카드는 위 계산을 문장으로 묶기만 합니다(만들어 팔기 / 만들어 팔면 손해 / 싸게 구하는 길). 모바일 하단 결과 바(`site_ux.js`)에도 같은 추천이 뜹니다.
- 허브 오일병(1,000)·포션 빈병(800)은 상점 정가라 입력 없이 고정 지출로 넣습니다. 나머지 재료는 체크를 끄면 자체 수급으로 보고 0메소로 계산합니다. 기회비용은 빠집니다.
- 입력값은 `localStorage`의 `wealthElixirCalc` 하나에 저장됩니다. 메뉴 항목·NEW 배지는 `site_nav.js`에서 주입합니다.

## 약초 방치 게임

`herb_idle.html` + `herb_idle.css` + `herb_idle.js`(캔버스·입력·저장) + `herb_idle_core.js`(규칙·시세, DOM 없음). 캐릭터가 보라 약초(`icons/craft/보라약초.webp`)를 알아서 캐서 쥬니퍼베리 씨앗을 모으고, 버튼을 누르면 제련대·연금술 작업대로 가서 가공한 뒤 재료가 떨어지면 약초 캐기로 돌아옵니다. 씨앗·오일·재물비를 시세 보고 팔고, 연금술 재료는 시세 보고 사서 메소를 모으는 데까지가 기본 시스템이고, 메소 쓸 곳은 아직 없습니다.

- 채집: 1회 2초, 캔 약초는 10~16초 뒤 다시 자람. 씨앗은 **3번 중 1번꼴로 1~5개**(평균 1개). [에펨코리아 채집량 통계](https://www.fmkorea.com/9640646044)의 500회당 평균 497.6개·표준편차 36.8에 맞춘 가정이며(이 규칙이면 500회 평균 500·표준편차 36.5), 글에는 500회 합계만 있습니다.
- 오일: 씨앗 6 + 허브 오일병 1,000메소 → 90% 오일. 나머지 10%는 보라색 가루가 나오는 **꽝**이라 가방에 남지 않고, 가루가 터져 **3초 기절**합니다(기절 중에 다른 일을 눌러도 깨어난 뒤 이동).
- 연금술: 오일 5 + 최상급 아이템 결정 2 + 현자의 돌 1 + 포션 빈병 800 → 재물비 6개. 결정·돌은 경매장에서 시세 보고 직접 사고(수수료 없음, "필요한 만큼"은 지금 오일을 다 쓸 만큼), 빈병만 메소에서 자동으로 빠집니다. 레시피는 있다고 봅니다. 도중에 다른 일을 누르면 넣은 재료는 돌려받습니다.
- 시세: 평소 값은 [채집 공략글](https://www.fmkorea.com/9472643295)의 2026년 2월 크로아 경매장 가격(씨앗 74만 · 오일 554만 · 재물비 475만 · 최상결 30만). 현자의 돌 30만은 확인한 시세가 아니라 가정입니다. 3초마다 다 같이 움직이는 흐름 + 품목별 흔들림(평균으로 돌아오는 랜덤워크)으로 바뀌고, 평균 2분 반에 한 번 가상 소식이 한두 품목을 크게 움직였다가 1분 반쯤에 절반으로 돌아옵니다. 변동폭은 원재료 **씨앗 > 오일 > 재물비**(가운데 80% 구간이 평소 대비 약 ±15% · ±10% · ±6%), 재료는 ±9% 정도이고, 품목마다 상·하한이 있습니다. 판매 수수료 5%.
- 자산: 팔아서 받은 메소만 셉니다. 가방 속 재고는 시세 따라 값이 바뀌어서 넣지 않습니다. 기록에는 판매·구매·시세 소식만 남기고, 가공 결과는 화면 안 알림으로만 보여 줍니다.
- 내 캐릭터: "캐릭터 바꾸기"에서 계정 캐릭터 선택기(`nexon_characters.js`, 레벨 10 이상)로 고르거나 이름을 적으면, 홈에서 등록한 API 키(`nexon_key.js`)로 `/id`(선택기로 고르면 건너뜀) → `/character/basic`을 불러 `character_image`로 그립니다. 동작은 A00 서기(0~2)·A02 걷기(0~3)·A16 휘두르기(0~3, 약초 캘 때), 기절할 때 표정 E05(당황), 무기 모션 W00. 이미지는 300×300 고정이라 서기 첫 프레임의 투명 픽셀에서 발 위치를 재서(`spriteAnchor`, 맨 아래 몇 줄의 가운데) 땅에 맞춰 세우고, 원본이 왼쪽을 보고 있어 오른쪽으로 갈 때 뒤집습니다. 넥슨 이미지 서버가 CORS(`Access-Control-Allow-Origin: *`)를 허용해서 픽셀을 읽을 수 있습니다. 불러온 캐릭터(이름·서버·레벨·직업·이미지 주소)는 `herbIdleCharacter`에 저장해 다음에는 API를 다시 부르지 않습니다. 이미지 주소는 넥슨 이미지 서버나 같은 사이트 주소만 받습니다.
- 시간: 벽시계 기준으로 프레임마다 흘리고, 탭을 숨기거나 창을 닫았다 와도 같은 `advance()`로 최대 8시간까지 따라잡습니다(1분 넘게 비우면 정산 창). 난수도 상태에 들어 있어 한 번에 흘리든 잘게 흘리든 결과가 같습니다.
- 저장: 게임은 `localStorage`의 `herbIdleGame` 하나. 두 탭에서 동시에 열면 나중 탭이 이어받고 먼저 탭은 멈춥니다.

검증: `node --test tests/herb-idle.test.cjs`

## 이벤트 코인샵 데이터 바꾸기

상점 품목·기간·주당 코인은 저장소 루트의 `CoinShopData.xlsx`가 원본입니다. 계산기 페이지는 이 파일을 직접 읽지 않고, `tools/build_coin_shop_data.js`가 xlsx를 `coin_shop_data.js`로 바꿔 준 결과를 읽습니다. Vercel 배포 때는 `vercel.json`의 빌드 명령으로 자동 변환되므로 **xlsx만 고쳐서 커밋하면 됩니다.** 로컬에서 미리 보려면 `node tools/build_coin_shop_data.js`를 한 번 실행합니다(외부 패키지 없음).

시트 네 개입니다. 첫 줄이 열 이름이고, 열 순서는 상관없습니다.

| 시트 | 열 | 뜻 |
|---|---|---|
| Event | EventID, Name, StartTime, EndTime, Weeks, WeekCoin | 이벤트 하나가 한 줄. StartTime은 1주차 시작일(목요일), EndTime은 상점 종료일, Weeks는 코인을 받는 주 수, WeekCoin은 주당 코인 |
| Shop | EventID, ItemID, Type, Coin, Value, Limit | 이벤트별 진열. Coin은 가격, Value는 구매 제한 수량, Limit은 M(메이플ID당) 또는 W(월드당). 줄 순서가 상점에 보이는 순서 |
| Item | ItemID, String, Icon | 공통 아이템. String은 이름, Icon은 `icons/coin-shop/` 안의 webp 파일명. 선택권처럼 아이콘이 둘이면 `a.webp|b.webp`. 비우면 기본 아이콘 |
| Type | TypeID, Name | 상점 탭(강화·성장 등) |

새 이벤트를 올리는 순서:

1. Event 시트에 한 줄 추가(EventID는 새 번호).
2. Shop 시트에 그 EventID로 품목 줄 추가. 이미 Item에 있는 아이템은 ItemID만 적고, 새 아이템은 Item 시트에 먼저 추가.
3. 새 아이콘은 webp로 `icons/coin-shop/`에 넣기.
4. 커밋. 페이지는 오늘 날짜가 기간 안에 드는 이벤트를 자동으로 고르고, 이벤트가 여럿이면 제목 아래 선택 상자가 나옵니다. 장바구니 저장은 이벤트별로 분리됩니다.

## 큐브 옵션 확률 데이터 갱신

`cube_option_data.js`는 넥슨 공식 확률 페이지(maplestory.nexon.com/Guide/OtherProbability/cube)의 "확률 검색"을 그대로 호출해 만든 자동 생성 파일입니다. 레전드리 등급, 큐브 4종(재설정·블랙 / 레드 / 명장·골드 / 에디셔널) × 장비 20종 × 0~250레벨 전부를 조회하고, 옵션표가 같은 레벨끼리 구간으로 묶습니다. 넥슨이 확률을 바꾸면 한 번 다시 돌리고 커밋합니다(약 2만 요청, 1분 이내).

```
node tools/fetch_cube_option_data.js
```

세 줄 중 최대 1개(쓸만한 스킬, 피격 후 무적시간)·최대 2개(피격 시 데미지 무시, 피격 시 무적) 규칙은 공식 페이지 설명대로 계산에 반영합니다(앞 줄에서 한도를 채우면 그 계열을 빼고 나머지 확률을 다시 나눔).

## 어센틱 심볼 계산기 — 캐릭터 불러오기 (넥슨 오픈 API)

페이지 맨 위 "캐릭터 검색" 카드에 캐릭터 이름을 적고 **캐릭터 검색**을 누르면 8개 지역 심볼의 현재 레벨이 자동으로 채워집니다. API에 없는 지역은 "미도착"으로 바뀝니다. 불러온 뒤에는 맨 아래 "현재 심볼 레벨" 카드가 접히며, 펼쳐서 수동으로 고칠 수 있습니다.

- 서버 없이 브라우저에서 [넥슨 오픈 API](https://openapi.nexon.com/)를 직접 호출합니다(`open.api.nexon.com`이 CORS를 허용하므로 `file://`로 열어도, GitHub Pages로 띄워도 동작). 호출 순서는 `/maplestory/v1/id?character_name=…`로 ocid를 받은 뒤 `/maplestory/v1/character/symbol-equipment?ocid=…`와 `/maplestory/v1/character/basic?ocid=…`을 함께 조회합니다. 기본 정보의 `character_image`와 이름·서버·레벨·직업은 `authentic_character_profile`에 저장해 새로고침 후에도 큰 캐릭터 프로필을 복원합니다.
- **API 키는 사용자가 직접 발급**해서 계산기 모음 홈 화면(`index.html`)의 "넥슨 오픈 API 키" 카드에 붙여넣어야 합니다(openapi.nexon.com 로그인 → 마이 페이지 → 애플리케이션 등록 → API Key). 홈에서 한 번만 등록하면 `localStorage`(`nexon_key.js`)를 통해 어센틱 심볼 계산기 등 API를 쓰는 모든 계산기 페이지에서 그대로 읽힙니다. 키와 마지막으로 조회한 캐릭터 이름(및 마지막으로 불러온 심볼 레벨)은 그 브라우저에만 저장되고 넥슨 API 호출 외에는 어디에도 보내지 않습니다. 페이지에 키를 하드코딩하지 않은 이유는 정적 사이트라 소스가 그대로 노출되기 때문입니다. 계산기 페이지에서 키 없이 불러오기를 누르면 홈 화면(`index.html#apiKey`)으로 안내합니다.
- 보스 수익 계산기는 같은 키로 닉네임의 OCID를 찾은 뒤 `/maplestory/v1/scheduler/character-state?ocid=…`를 호출합니다. 응답에서 등록된 주간·월간 보스와 완료 상태를 가져와 기존 결정석 가격표에 연결하며, API에 없는 파티 인원은 사용자가 정한 값을 재조회 뒤에도 유지합니다. `/maplestory/v1/character/basic?ocid=…`의 `character_image`도 함께 저장해 캐릭터 카드에 현재 외형을 표시하고, 예전에 저장한 API 연동 캐릭터는 다음 진입 때 이미지를 보충합니다. 오늘 스케줄러를 조회할 때는 `date` 파라미터를 보내지 않습니다.
- **한 번 등록하면 계속 유지됩니다.** 이미 등록된 상태에서는 홈 화면에 입력창·저장·삭제 버튼이 보이지 않고 "API 키 등록됨 ✓" 문구만 남습니다. 키를 재발급했거나 잘못 입력한 경우처럼 드물게 바꿔야 할 때만 "키 변경 / 삭제" 링크를 눌러 폼을 다시 엽니다.
- 심볼 매핑은 응답의 `symbol_name`("어센틱심볼 : 세르니움", "그랜드 어센틱심볼 : 탈라하트" 등)에서 **지역 이름 부분일치**로 찾습니다. 접두어 표기가 바뀌어도 깨지지 않게 하려는 것이고, 레벨은 `symbol_level`을 그대로 씁니다(비어 있으면 `symbol_force`/10으로 역산).
- "외부 획득 포스"는 API로 가져오지 않습니다(심볼 외 포스는 별도 입력).
- 오류는 넥슨 오류 코드(`OPENAPI00005` 잘못된 키, `OPENAPI00007` 호출 한도 초과 등)를 한글 안내로 바꿔서 보여줍니다. 캐릭터 이름 조회 단계의 `OPENAPI00003/00004`는 "캐릭터를 찾을 수 없습니다"로 표시합니다.

## 주흔 기댓값 계산기

아이템과 진행할 작(확률)을 선택하는 순간부터 버튼 없이 자동으로 계산돼요.

## 주흔작이란

잠재능력 등급(레어/에픽/유니크/레전드리)과는 **무관한 별개 시스템**입니다. 장비마다 "업그레이드 가능 횟수"(= N작)가 정해져 있고, 아케인셰이드의 주문서로 한 번씩 시도해 성공시켜야 합니다. 부위는 무기/모자/방어구/장갑 4개로만 다룹니다(상의·하의·망토·신발·한벌옷은 전부 "방어구"로 취급 — 작 수·비용 테이블이 동일하므로).

| 부위 | 작 수 |
|---|---|
| 무기 | 9작 |
| 모자 | 12작 |
| 방어구 | 8작 |
| 장갑 | 8작 |

아케인셰이드 시도는 100%/70%/30%/15% 네 확률 구간 중 **하나를 골라서 N작 내내 그 구간으로 반복 진행**합니다(구간을 섞어 쓰지 않음). 확률·비용은 아이템 레벨과 확률 모드(기본/FEVER)·보너스에 따라 자동으로 정해지는 고정값이라 직접 입력할 게 없습니다(`app.js`의 `WEAPON_COST`/`ARMOR_COST`/`GLOVE_COST`, `PROB_PRESET`).

## 이노센트 / 아크이노센트 / 순백

셋 다 부위·레벨과 무관하게 항상 고정 비용입니다:

- **이노센트**: 12,000 주흔 — 0작으로 초기화. 카드를 누르면 선택, 다시 누르면 해제
- **아크 이노센트**: 24,000 주흔 — 0작으로 초기화 (이노센트와 아크이노센트는 둘 중 하나만 선택 가능)
- **순백**: 20,000 주흔 — 실패해도 작 유지.

이노센트/아크이노센트와 순백 모두 "**어떤 도구를 쓸지**"(초기화 방식 선택, 순백은 항상 있다고 가정)와 "**그걸 주흔으로 조달했는지**"(각각의 "주흔으로 조달" 체크, 이미 외부에서 갖고 있으면 해제)를 따로 다룹니다. 이 둘이 전략에 반영되는 방식은 서로 다릅니다:

- **이노센트/아크이노센트 조달 여부는 전략(그리고 "총 기대 시도 횟수")에도 반영됩니다.** 조달 안 했으면(내 주흔을 안 쓰면) resetCost를 0으로 놓고 정책을 다시 짭니다. 그래야 "조달 안 하면 이노센트든 아크 이노센트든 어차피 똑같이 무료로 전체 초기화하는 것뿐"이라는 사실이 전략에 정확히 반영되어, **조달을 껐을 때는 이노센트를 골랐든 아크 이노센트를 골랐든 "지금 할 일"·"총 기대 시도 횟수"·"기대 주흔"이 완전히 동일**해집니다. 조달했을 때만 이노센트(12,000)와 아크 이노센트(24,000)의 실제 가격 차이가 전략에 반영되어 서로 달라집니다(아크 이노센트가 더 비싸니 초기화를 덜 추천 → 시도 횟수도 더 적게 나옴, 진행을 덜 날리므로).
- **순백 조달 여부는 전략에 영향을 주지 않습니다.** 순백은 "저렴한 순백/비싼 순백" 같은 대안이 없어서 이노센트·아크이노센트처럼 "모드 간 결과가 같아야 한다"는 요구 자체가 성립하지 않기 때문에, 항상 표준가(20,000)로 전략을 고정해 "총 기대 시도 횟수"가 순백 조달 여부와 무관하게 안정적으로 유지되게 합니다. 조달 체크는 화면에 보이는 **"기대 주흔" 숫자에만** 반영됩니다(조달 안 했으면 순백 비용만 0원으로 재평가).

**손절 기준표는 이 둘(초기화 방식·조달 체크)과 별개로, 항상 이노센트=12,000 / 아크이노센트=24,000 표준가로 고정한 참고표 두 개**를 보여줍니다(뭘 선택했든 안 바뀜) — 자세한 건 아래 "손절 기준표" 설명 참고. (계산상: `calc.js`의 `solve()`를 손절 기준표용으로는 표준가 고정 입력으로, "전체 기댓값"/"지금 상태 확인하기"용으로는 이노센트·아크이노센트의 실제(조달 반영) 비용을 입력으로 각각 따로 호출하고, 순백만 `evaluate()`로 한 번 더 재평가합니다.)

**중요: 실패해도 성공 작 수(S)는 안 줄지만, "무료로 다시 시도할 수 있는 슬롯"(R)은 줄어듭니다.** 시도는 성공이든 실패든 R을 1개 소비하고, 순백은 그 소비된 R을 1개 복구합니다(성공작은 그대로 두고). 그래서 상태는 성공 작 수 하나만으로 정해지지 않고 **(S=성공 작 수, R=남은 무료 슬롯)** 두 값으로 정해집니다 — 같은 1성공이라도 "2번 시도해서 1성공"과 "8번 다 써서 1성공"은 R이 달라서 비용 구조가 전혀 다릅니다.

매 상태에서 아래 세 가지 중 기대비용이 가장 낮은 걸 자동으로 고릅니다:

1. **그냥 주흔 시도** — 비용 `m`, 확률 `l`로 성공(S+1,R-1), 실패하면 그 자리에서 다시 "순백 쓸지 말지" 비교(자기참조)
2. **순백만 먼저 쓰기** — 비용 20,000, 실패로 소모된 슬롯이 있을 때 R만 1 복구 (`S+R<N`; R=0이라 시도 자체가 불가능할 때 특히 중요한 선택지)
3. **이노센트/아크이노센트** — 비용 12,000/24,000, (0, 총작수)로 완전 초기화

**주흔 반값** 이벤트를 켜면 주흔 시도 비용(`m`)뿐 아니라 이노센트/아크이노센트/순백 고정값도 전부 절반으로 계산합니다(카드에 표시되는 비용도 같이 바뀝니다). 실제 가격이 바뀌는 이벤트라 전략(ACT)을 정할 때 쓰는 표준가 자체가 반값이 되고, 그 결과 총 기대 주흔도 정확히 절반이 됩니다.

결과 패널(우측, 스크롤해도 고정)은 위에서부터 **전체 기댓값 / 지금 상태 확인하기 / 손절 기준표** 세 카드로 나뉘어 있습니다.

**"지금 상태 확인하기"**는 장비 작 수만큼 칸이 생기고, 클릭할 때마다 미시도→성공→실패→미시도로 순환합니다("초기화" 버튼으로 한 번에 전부 미시도로 되돌릴 수 있음). 몇 번을 어떤 순서로 눌러도 결과는 같아요(개수만 셈). 클릭한 즉시 "진행 상황(N작 시도 중 M작 성공)/지금 할 일(주흔 시도·순백·이노센트 중 하나, 크게 강조)/여기서부터 기대 주흔" 세 카드가 갱신됩니다. 이 추천은 위에서 설명한 대로 지금 골라둔 초기화 방식(이노센트/아크이노센트/해제)을 그대로 따릅니다 — 예를 들어 아크 이노센트를 선택하면 같은 실패 횟수에도 초기화 추천이 더 늦게 나옵니다. 상단 "전체 기댓값" 카드도 같은 전략을 씁니다.

**"손절 기준표"**는 접혀 있는 보조 카드로, 표를 두 개 보여줍니다 — 이노센트(12,000) 표준가로 고정한 표와 아크 이노센트(24,000) 표준가로 고정한 표(초기화가 더 비싼 만큼 손절 기준이 뒤로 밀립니다). 이 두 표는 **초기화 방식 선택과 무관하게 항상 그대로**인 순수 참고 자료입니다 — "지금 이노센트로 갈까 아크로 갈까"를 미리 비교해보라는 용도예요. 둘 중 지금 실제로 선택한 방식과 같은 표에는 "지금 선택과 같아서 '지금 할 일'이 이 표를 따라요"라는 표시가 붙습니다.

## 계산 로직

`calc.js`의 `solve()`가 핵심 엔진입니다. 상태 `(S,R)`에 대해 아래 값을 value iteration으로 계산합니다.

```
V(S,R) = min(
  resetCost + V(0, n),                                                    // 이노센트/아크이노센트
  protectCost + V(S, R+1),                                                // 순백만 먼저 쓰기 (S+R<n일 때)
  m + l·V(S+1,R-1) + (1-l)·min(protectCost + V(S,R), V(S,R-1))           // 주흔 시도 (R>0일 때)
)
```

n=총 작 수, m=주흔 1회 비용, l=성공확률. 세 번째 항의 `min(protectCost+V(S,R), V(S,R-1))`은 "방금 실패했을 때 순백으로 되돌릴지, 슬롯 하나를 그냥 잃고 넘어갈지"를 그 자리에서 비교하는 부분이라 자기참조가 생기는데, value iteration으로 반복 수렴시켜 풉니다.

**이 두 번째 항(순백만 먼저 쓰기)을 빠뜨리면 계산이 완전히 틀어집니다** — R=0이 되면 시도 자체가 불가능해서 이 옵션 없이는 무조건 초기화로 몰리는데, 실제로는 훨씬 저렴하게 R만 복구하고 계속 진행하는 게 나은 경우가 많습니다. (8작·39%·910주흔·이노12,000·순백20,000 조건에서 이 항을 빠뜨리면 256,410으로 계산되지만, 제대로 넣으면 220,871로 — 약 14% 차이가 납니다.)

**첫 번째 항(초기화)은 딱 한 곳, `(S,R)=(0,n)` 상태에서는 제외합니다** — 이미 초기화된 상태에서 또 초기화하는 건 자기 자신으로 돌아가는 아무 의미 없는 행동이기 때문입니다. `resetCost`가 0(예: 이노센트를 이미 조달해둬서 이 상태 계산에서는 공짜로 취급하는 경우)이면, 이 자기참조가 "V(0,n) = 0 + V(0,n)"이라는 식으로 그 상태의 현재 값을 그대로 베끼는 꼴이 되어 value iteration이 진짜 기대비용(반드시 시도를 거쳐야 나오는, 0보다 큰 값)으로 자라나지 못하고 0에 멈춰버리는 퇴화 고정점에 빠집니다. 이 예외 처리가 없으면 "초기화 도구를 조달 안 했다"고 체크하는 순간 기대 주흔이 통째로 0으로 튀어버리는 심각한 오류가 납니다.

## 아이템 데이터

`app.js`의 `TIER_ITEMS`에 티어(파프니르/앱솔랩스/아케인셰이드/에테르넬)별 부위 대표 아이템(아이콘 ID·이름·레벨)을 하드코딩했습니다. 아이콘은 [maplestory.io](https://maplestory.io)(KMS 389)에서 받아 `icons/trace/{아이템 ID}.webp`로 저장해 둔 파일을 씁니다.

파프니르 방어구·에테르넬 장갑은 maplestory.io 아이템 데이터베이스(KMS 389 스냅샷)에는 해당 이름의 아이템이 없었지만(파프니르=무기 전용, 에테르넬=모자/상의/하의만), 사용자 확인에 따라 계산기에는 포함해뒀습니다 — 비용은 레벨 기준 표(파프니르=150레벨 방어구 비용, 에테르넬=250레벨 장갑 비용)를 그대로 쓰고, 아이콘은 인접 티어의 같은 부위(방어구/장갑) 아이콘으로 대신합니다(무기·모자 등 다른 부위 아이콘을 잘못 보여주는 것보다는 실루엣이라도 맞는 게 나아서). 정확한 개별 아이콘은 아니라서 아이템 미리보기에 "아이콘은 유사 부위로 대체"라고 표시됩니다.

## 시드링 뽑기

`seedring_gacha.html`은 보스 반지 상자(녹옥/홍옥/흑옥/백옥/생명)를 여는 시뮬레이터입니다. 인게임과 같은 2단 추첨을 그대로 구현했습니다 — 먼저 반지 종류를 뽑고, 반지가 나온 경우에만 레벨을 뽑습니다(생명의 연마석은 레벨 추첨 없음). 따라서 화면에 표시되는 최종 확률은 `종류 확률 × 레벨 확률 / 100`입니다. 각 상자의 종류·레벨 목록은 로드 시 합이 정확히 100%가 되도록 정규화합니다.

- **모드** — "무한 뽑기"는 상자를 골라 제한 없이, "오늘의 뽑기"는 그날 지정된 상자로 하루 한 번만 돌립니다. 지정 상자는 한국 시간(`Asia/Seoul`) 날짜의 UTC 일수 기준으로 흑옥/백옥이 하루씩 교대하며, 뽑은 결과는 `localStorage`(`seedringDailyDrawV1`)에 날짜와 함께 저장해 같은 날 다시 뽑지 못하게 막습니다. 저장된 날짜·상자가 오늘 기준과 어긋나면 무시하고 새로 뽑을 수 있게 합니다.
- **당첨 판정** — 리스트레인트 링 Lv.4, 컨티뉴어스 링 Lv.4, 생명의 연마석.
- **결과 공유** — 결과 카드를 1080×1080 캔버스로 그려 클립보드에 복사합니다. 복사가 차단되는 브라우저에서는 PNG로 내려받습니다. 반지·상자 아이콘은 `icons/seedring/`에 있고, 캔버스가 `file://`의 이미지 보안 제한(캔버스 오염)에 걸리지 않도록 같은 아이콘을 base64 data URI로도 파일 안에 내장해뒀습니다.
- 확률 수치는 공식 확률표가 아니라 [커뮤니티 정리 자료](https://matsu1207.tistory.com/144)를 바탕으로 재구성한 추정치입니다.

## 아이템 획득량 계산기

`hunting_calc.html`은 30분 사냥 기준입니다. 아획, 메획, 몬스터 레벨, 맵 마릿수를 입력하며 선택 사항인 6분 처치 수는 입력 시 × 5로 우선 적용합니다. 미입력 시 7.5초마다 모든 몬스터를 처치한다고 보고 맵 마릿수 × 240을 사용합니다. 실측 0은 0마리로 계산합니다.

조각은 인벤 게시글(https://www.inven.co.kr/board/maple/2304/37701)의 로그 추정식만 사용합니다. 260 이상 몬스터 및 6차 전직·조각 드랍 가능 사냥터를 가정합니다. 주머니 확률은 min(1, 0.6 × (1 + 아획/100))이며 아획 67% 이상은 100%입니다. 몬스터 레벨 × 6 / 7.5 / 9를 적용한 순수 메소 및 메획 적용 메소의 최소·기대·최대를 카드로 표시합니다. 최소·최대는 주머니 금액 시나리오이며 보장 범위가 아닙니다. 캐릭터 레벨·일일 누적·상한은 계산에서 제외합니다.

실제로 얻은 30분 조각 수를 입력하면 이항분포의 상측 누적확률 P(X ≥ 획득 개수)를 상위 N%로 표시합니다. 몬스터별 독립·최대 1개 드랍을 가정하며 동률을 포함한 추정 확률이고 실제 유저 순위는 아닙니다. 빈 입력은 미표시, 0개는 상위 100%, 모델상 불가능한 획득량은 조건 확인으로 안내합니다.

검증: `node --test tests/hunting-calc.test.cjs`
