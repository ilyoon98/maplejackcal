# 메이플 계산기 공통 UI 기획서

신규 기능과 변경하는 화면에 적용한다. 사용자가 어느 페이지에서든 현재 위치를 파악하고, 조건을 입력하고, 결과를 확인하는 방법을 쉽게 찾을 수 있게 한다. 화면 유형에 따라 본문 배치를 선택하고, 같은 역할의 메뉴, 카드, 버튼, 상태 문구는 같은 방식으로 표시한다. 아래 예시에서는 유형에 해당하는 구조를 참고한다.

저축 조건을 바꿔 보면서 입력 카드, 대표 결과, 도움말과 모바일 배치를 비교할 수 있다. [주간 메소 목표 계산기 프로토타입](prototypes/common-ui-preview.html)

버튼을 눌러 보고 선택, 켜짐과 꺼짐, 목록 열기, 토스트와 확인창을 한 화면에서 비교할 수 있다. [공통 UI 구성 요소 미리보기](prototypes/ui-components.html)

## 글자와 강조

시스템 글꼴을 사용하고 기본 크기 16px을 기준으로 `rem`으로 작성한다. 숫자, 단위, 버튼 이름은 실제 데이터에서 가장 긴 값과 200% 확대 상태로 확인한다.

| 역할 | 크기와 굵기 | 색과 배치 |
| --- | --- | --- |
| 페이지 제목 | PC 30px, 모바일 22px, 750 | 기본 글자색. 줄 높이 1.35 |
| 카드 제목과 소제목 | 18px / 16px, 700 | 기본 글자색. 다음 내용과 각각 12px / 8px |
| 본문 | 15px, 400 | 기본 글자색. 줄 높이 1.6 |
| 입력 라벨과 버튼 | 14px, 650 | 기본 글자색. 입력값은 PC 15px, 모바일 16px |
| 보조 안내와 단위 | 13px, 400 | 보조 글자색. 입력이나 관련 값 바로 아래에 4~6px 띄움 |
| 배지와 부가 상태 | 12px, 650 | 상태 글자색. 단어 또는 짧은 구로 표시 |
| 대표 결과 | PC 32px, 모바일 26px, 750 | 기본 파랑 또는 의미에 해당하는 상태색. 단위는 14px |

한 문단의 굵은 글씨는 사용자가 결정에 쓰는 값이나 다음 행동에 쓴다. 안내 문장은 일반 굵기로 쓰고, 경고와 오류는 `주의`, `입력 오류`처럼 상태명을 붙인다. `·`로 안내를 나열하는 표현은 최대한 줄인다. 관련 있는 항목은 `과`, `와`로 연결하고, 서로 다른 조건은 문장이나 행을 나눈다. 저장 위치를 알릴 때는 `이 브라우저에 저장했습니다.`처럼 한 문장으로 쓴다.

## 크기와 간격

| 위치 | 기본 규격 |
| --- | --- |
| 화면 | 최대 1,280px. 좌우 16px, 상단 24px. 카드 사이 16px |
| 카드 | 모서리 12px. 안쪽 여백 PC 20px, 모바일 16px. 본문 그룹 사이 16px |
| 입력칸과 버튼 | 높이 최소 44px. 모서리 8px. 좌우 12px, 상하 8~10px. 내용이 늘면 높이도 늘림 |
| 라벨, 단위, 아이콘 | 라벨과 입력 사이 6px. 아이콘과 글자 사이 6~8px. 필드 사이 12~16px |
| 버튼 묶음 | 버튼 사이 8px. 공간이 부족하면 다음 줄로 이동. 아이콘만 있는 버튼도 44×44px |
| 표 | 셀 상하 8px, 좌우 12px. 숫자는 오른쪽, 문장은 왼쪽. 넓은 표의 스크롤은 표 영역 안에 둠 |
| 팝업과 토스트 | 확인창 최대 560px, 좌우 화면 여백 최소 16px. 안쪽 여백 PC 24px, 모바일 16px. 토스트 최대 400px |

간격은 4, 8, 12, 16, 20, 24, 32px 단위를 우선 사용한다. 입력칸에는 단위가 보일 공간을 남기고, 선택 영역과 입력 영역이 나란히 들어가기 어려우면 한 열로 바꾼다. 같은 카드에서 주요 버튼 하나를 강조한다. 실제 확인 버튼은 설명과 취소 뒤에 배치한다.

## 조작 종류와 상태

| 조작 | 기본 형태와 상태 | 키보드와 동작 |
| --- | --- | --- |
| 실행 버튼 | 주요 행동은 파란 채움, 보조 행동은 어두운 배경과 테두리. 마우스를 올리면 테두리가 밝아지고 누르는 동안만 배경이 어두워진다. | Enter 또는 Space로 실행. `파티 저장`처럼 동작과 대상을 표시 |
| 선택형 버튼 | 선택 전에는 보조 버튼, 선택 후에는 파란 배경과 테두리, 체크 표시. `aria-pressed`로 현재 상태를 제공한다. | 눌러서 선택을 바꾸며 선택 상태는 손을 뗀 뒤에도 유지 |
| ON/OFF 스위치 | 기능을 즉시 켜거나 끌 때 사용한다. OFF는 회색 트랙과 왼쪽 손잡이, ON은 파란 트랙과 오른쪽 손잡이. `켜짐/꺼짐`이나 `보유/미보유`를 표시한다. | 안정적인 이름을 유지하고 `role="switch"`와 `aria-checked`로 상태 제공. Space로 전환 |
| 라디오 | 하나만 고르는 항목. 원형 표시 안에 선택 점. 그룹 이름을 표시한다. | `<fieldset>`과 `<legend>` 또는 접근 가능한 그룹 이름. 방향키로 이동 |
| 체크박스 | 독립 항목을 여러 개 고른다. 사각형 체크, 일부만 선택된 전체 선택에는 가로선을 쓴다. | 라벨 전체를 눌러 변경. Space로 전환. 부분 선택은 `indeterminate` 사용 |
| 탭 | 한 영역의 보기 전환. 현재 탭에 파란 밑줄 또는 채움과 굵은 글자를 적용한다. | `aria-selected`와 연결된 패널 사용. 방향키로 탐색 |
| 드롭다운 | 기본 `<select>` 사용. 닫히면 선택값과 아래 화살표를 표시한다. 열리면 지원 브라우저에서 위 화살표와 파란 테두리를 표시한다. 열린 옵션 목록은 브라우저와 운영체제의 기본 모양을 따른다. | 클릭 또는 Alt+↓로 열고 방향키로 탐색한다. Enter로 선택하고 Esc로 닫는다. 긴 옵션은 펼친 목록에서도 의미를 구분할 수 있게 이름을 쓴다. |
| 펼침과 접힘 | 선택을 바꾸지 않고 아래 내용을 보이게 할 때 사용한다. 화살표 방향과 `aria-expanded` 또는 `<details>`의 `open` 상태를 함께 바꾼다. | Enter 또는 Space로 전환. 열린 팝업 메뉴를 Esc로 닫으면 연 버튼으로 돌아간다. |
| 입력과 슬라이더 | 입력값과 단위는 가까이 둔다. 입력 오류는 테두리와 설명을 함께 표시한다. 슬라이더에는 현재 값과 단위를 라벨 옆에 쓴다. | 라벨 연결, 오류 메시지와 필드 연결. 슬라이더는 방향키로 한 단계씩 조절 |
| 링크와 앵커 | 파란색 밑줄로 이동임을 표시한다. 본문 앵커는 제목으로 이동하고 상단에서 16px 또는 고정 헤더 높이만큼 여백을 둔다. | 같은 문서 이동 뒤 대상 제목으로 포커스를 옮긴다. 고정 버튼 뒤에 가려지는지와 뒤로 가기 동작을 확인 |

키보드 포커스는 파란 3px 외곽선으로 표시하고 3px 띄운다. 포커스와 선택 표시는 동시에 보일 수 있어야 한다. 비활성 상태는 채도와 대비를 줄이고 이유를 가까이 쓴다. 처리 중에는 버튼을 같은 자리에 두고 `저장 중…`처럼 현재 작업을 알리며 중복 실행을 막는다. 눌림 표시가 나와도 레이아웃이나 글자 위치는 그대로 유지한다.

## 카드와 입력 상태

| 상태 | 카드 | 글자와 입력칸 |
| --- | --- | --- |
| 기본 | 기본 배경, 얇은 카드 테두리 | 제목은 기본색과 700 굵기. 입력값은 기본색, 설명과 단위는 보조색 |
| 대표 결과 | 파란 테두리. 카드 크기와 안쪽 여백은 기본 카드와 같음 | 대표 숫자만 750 굵기와 결과색. 설명은 일반 굵기, 단위는 숫자 옆에 둠 |
| 선택 가능 및 선택됨 | 눌러서 선택할 수 있는 카드에만 마우스 올림 반응을 줌. 선택되면 파란 테두리와 체크 표시 | 제목과 값은 기본색을 유지하고 현재 선택을 텍스트나 체크로 표시 |
| 펼침 | 테두리와 여백을 유지한 채 상세 영역만 아래로 펼침 | 펼침 제목과 방향 표시를 파란색으로 강조. 상세 내용은 기본 글자색 |
| 비활성 | 선택 강조를 해제하고 사용 조건을 카드 안에 표시 | 조작은 `disabled`로 제공. 비활성 입력값과 별도로 이유는 읽을 수 있는 보조색 유지 |
| 조회 중 또는 일부 결과 | 카드 위치를 유지하고 대표 결과 가까이에 조회 중 또는 일부 결과 표시 | 기존 값이 있으면 기준 시점을 함께 표시. 입력 중인 값과 오류 안내는 계속 읽을 수 있게 둠 |
| 입력 오류와 읽기 전용 | 해당 입력을 담은 카드의 일반 구조를 유지 | 오류는 필드 테두리와 바로 아래 해결 안내. 읽기 전용은 값의 대비를 유지하고 복사 가능. 입력 예시는 라벨과 별도로 제공 |

## 토스트와 팝업

| 구성 요소 | 위치와 표시 기준 |
| --- | --- |
| 토스트 | 저장 성공처럼 짧은 피드백을 우측 하단에 표시한다. 모바일에서는 좌우 16px을 남기고 고정 하단 버튼 위에 둔다. 상태 이름과 결과를 표시하고 4초 뒤 닫는다. 사용자가 직접 닫을 수도 있다. `role="status"`를 사용하고 현재 포커스를 유지한다. |
| 오류와 주의 | 고쳐야 하는 문제는 입력 또는 실행 버튼 가까이에 표시하고 해결 방법을 쓴다. 사용자가 고칠 때까지 볼 수 있게 둔다. 즉시 알릴 오류에만 `role="alert"`를 사용한다. |
| 확인창 | 작업을 계속하려면 선택이 필요한 경우 화면 중앙에 `<dialog>`를 연다. 제목에 대상과 동작, 본문에 범위를 쓴다. 되돌리기 어려운 작업은 취소에 먼저 포커스를 두고 Esc도 취소로 처리한다. 닫으면 연 버튼에 포커스를 돌려준다. |
| 도움말과 툴팁 | 긴 도움말은 공통 도움말 패널에 둔다. 짧은 보충 설명은 툴팁으로 제공하고 포커스로도 열 수 있게 한다. 진행에 필요한 정보와 오류 해결 방법은 본문에 둔다. |
| 배지, 진행 표시, 빈 상태 | `보유`, `완료`, `3 / 9`처럼 뜻이나 진행량을 표시한다. 빈 영역에는 이유와 바로 할 수 있는 다음 행동을 적는다. |

## 확인한 기존 화면

공개 화면 25개를 브라우저에서 열고 첫 진입 상태의 제목, 본문, 조작 요소를 비교했다. 공통 헤더의 제목 크기는 같지만, 카드 제목은 약 14~24px로 달랐다. 선택형 버튼은 홈 분류와 장신구 선호 옵션, ON/OFF는 주흔 설정과 스타포스 파괴방지, 라디오는 코인샵 주차 선택, 체크박스는 스타포스 로그와 제작 단계에서 각각 확인했다.

공용 환산 배율의 토스트는 상단에, 약초 채집소의 토스트는 게임 장면 안에 표시된다. 확인창도 브라우저 확인창과 화면 안의 대화상자가 섞여 있다. 위 표를 기준으로 새 구현과 기존 화면의 변경분을 비교한다. [공용 환산 배율](../shared_boss_rates.html), [달빛 약초 채집소](../herb_idle.html), [스타포스 로그](../starforce_history.html)

## 공통 화면 구조

화면 상단은 **공통 메뉴 → 페이지 제목과 한 줄 설명 → 본문** 순서로 구성한다. `<h1>`은 하나만 쓰고 홈 카드 및 메뉴와 같은 기능 이름을 사용한다. 한 줄 설명에는 사용자가 얻는 결과를 쓴다. 예를 들어 장신구 맞추기에서는 `장신구 9부위에 드랍과 메획을 배치해 장비 상한을 채워 보세요.`처럼 작업과 목표를 함께 보여준다. 공식과 출처, 고급 설정은 `? 도움말` 또는 접힌 `계산 기준`에 둔다. 현재 결과를 해석하는 데 필요한 적용 조건은 숫자 옆에 표시한다. ## 카드와 버튼

- 공통 `.wrap`으로 최대 너비 1,280px과 좌우 여백 16px을 맞춘다. 카드에는 `.card`를 사용하고 기본 모서리는 12px로 한다. 배경, 테두리, 기본 글자색은 `--card`, `--border`, `--text`를 따른다. 보조 문구에는 `--ux-muted`를 사용한다. 페이지 전용 CSS는 루트 클래스 아래에 배치하고, 기능 고유의 표, 차트, 배치에 사용한다. [공통 스타일](../style.css)
- 같은 작업 영역에서 대표 결과 카드와 주요 버튼을 각각 하나씩 강조한다. 동등한 핵심 수치가 여러 개면 한 카드 안에 묶는다. 일반 화면의 전체 폭 주요 버튼은 `button.primary`, 보스 작업 화면은 `.boss-primary`, 보조 버튼은 `.ux-button`을 우선 사용한다. 주요 버튼이 인라인으로 필요하면 기존 강조 색과 버튼 규격을 따른다. [공통 스타일](../style.css), [공통 UX](../site_ux.css), [보스 작업 UI](../boss_workspace.css)
- 제목, 홈 카드, 펼침 메뉴의 아이템 아이콘은 기본 32px, 480px 이하에서는 24px 정사각형 안에 원본 비율로 표시한다. 상단 탭 아이콘은 기본 20px, 480px 이하에서는 16px로 표시한다. 장비 외형이나 게임 장면의 이미지 크기는 콘텐츠 배치에 맞춘다. [공통 스타일](../style.css)
- 버튼 이름은 결과가 드러나는 동사로 쓴다. `파티 만들기`, `파티 저장`, `빈 줄로 목표 채우기`처럼 대상과 동작을 함께 적는다. 취소는 편집 영역에, 삭제와 전체 초기화는 저장 버튼과 구분되는 위치에 둔다. 복구할 수 없는 삭제나 초기화는 적용 전에 대상과 범위를 보여준다.

## 입력과 결과 표시

- 입력칸마다 라벨을 연결하고 `메소`, `%`, `개` 같은 단위는 라벨 또는 값 가까이에 둔다. 선택 입력은 무엇을 비워도 되는지, 비워두면 어떤 기준을 적용하는지 함께 표시한다. 값이 잘못되면 해당 입력칸 가까이에 허용 범위나 해결 방법을 표시한다.
- 일반 입력과 단일 선택 드롭다운은 최소 높이 44px, 모서리 8px을 기본으로 한다. 드롭다운은 브라우저 기본 `<select>`로 구현하고, 닫힌 상태에서 공통 화살표와 선택값이 보이게 한다. 달력 내부의 월 선택은 달력의 조작 규격을 따른다. [공통 입력 스타일](../site_ux.css)
- 즉시 계산할 수 있는 결과는 입력 변경에 맞춰 갱신한다. 조회, 저장, 자동 배치처럼 실행 시점이 중요한 작업에는 해당 동작 버튼을 둔다. 자동 갱신 화면의 도움말과 버튼 실행 화면의 도움말은 각 동작에 맞게 쓴다.
- 결과 카드에서는 **대표 값과 단위 → 결과에 적용한 조건 → 상세 내역** 순서로 읽히게 한다. `30분 기대 획득량`, `수수료 반영 순이익`처럼 숫자의 기준을 제목에 드러낸다. 상세 수식이나 긴 비교표는 `.ux-details`를 적용한 `<details>`로 펼쳐 볼 수 있게 한다. [공통 UX](../site_ux.css)
- 금액은 큰 값의 비교가 쉽도록 억과 만 단위를 사용하고, 입력, 계산, 저장에는 원래 정밀도를 유지한다. 표시에서 반올림하거나 생략하는 경우 기준을 상세에 적는다. 실제 값 `0`과 아직 구할 수 없는 값 `—`을 구분한다. 퍼센트와 퍼센트포인트는 각각 `120%`, `20%p 부족`처럼 표기한다.

## 상태별 표시

| 상태 | 화면 동작 | 문구 예시 |
| --- | --- | --- |
| 입력 전 | 필요한 조건과 다음 동작을 결과 영역에 안내한다. | `장비와 목표 별을 선택하세요.` |
| 처리 중 | 실행한 작업 가까이에 진행 상태를 표시하고 중복 요청을 막는다. | `강화 기록 불러오는 중…` |
| 빈 결과 | 조회가 끝났음을 알리고, 조건을 바꿀 수 있으면 안내한다. | `선택한 기간에 강화 기록이 없습니다.` |
| 실패 | 작성 중인 값과 마지막 정상 데이터를 보존한다. 이전 결과를 보여줄 때는 기준 시점을 표시하고, 다시 시도할 방법을 제공한다. | `기록을 갱신하지 못했습니다. 다시 시도` |
| 완료 | 요청이 성공한 뒤 작업한 영역에서 완료를 표시한다. 저장 기능은 범위를 명시한다. | `이 브라우저에 저장했습니다.` |

기대값, 추정값, 일부 조회 결과는 해당 숫자 가까이에 표시한다. 성공, 경고, 실패에는 색과 함께 상태명을 표시한다. 조회나 저장을 완료한 뒤 바뀌는 메시지는 `role="status"` 등으로 보조 기술 사용자에게도 알린다.

## 모바일과 키보드

- 계산기의 기본 전환점은 공용 `.layout`과 같은 960px로 두고, 그 이하에서는 입력과 결과를 한 열로 표시한다. 결과가 아래로 멀어지면 기존 `결과 보기` 이동 버튼을 재사용한다. 고정 요소를 사용할 때는 하단의 입력과 버튼을 가리지 않도록 여백을 둔다. [공통 스타일](../style.css), [결과 이동 동작](../site_ux.js)
- 스타포스 기댓값 계산기는 모바일에서도 기대 메소를 첫 화면에 표시한다. 결과 카드를 위에 두고 조건을 그 아래에 배치한다. 결과 카드가 화면 밖에 있을 때 하단에서 바로 이동할 수 있다. [스타포스 계산기](../starforce_calc.html)
- 긴 제목, 캐릭터 이름, 메소 금액은 줄바꿈할 수 있게 한다. 가로로 넓은 비교표는 제목과 주요 열을 읽을 수 있도록 표 영역 안에서만 가로 스크롤을 허용한다. 모바일의 주요 조작은 누르는 영역을 최소 44×44px로 확보한다.
- 이동은 링크, 실행은 버튼, 선택은 용도에 맞는 폼 컨트롤로 구현한다. 아이콘만 있는 버튼에는 `aria-label`을 붙인다. 키보드 포커스는 화면에서 보여야 하며, 대화상자를 닫으면 연 버튼으로 돌아간다. 툴팁에 넣은 보충 설명은 키보드로도 열 수 있게 하고, 진행에 필요한 안내는 화면 본문에 둔다. [공통 UX](../site_ux.js), [공통 툴팁](../site_tooltips.js)

## 구현에 사용하는 공용 파일

1. 새 페이지는 `style.css` → `site_ux.css` → 기능별 CSS 순으로 불러온다. 본문 상단에 `<div data-site-navigation></div>`를 두고 `site_header.js` → `site_nav.js` → `site_ux.js` 순으로 `defer`를 적용한다. 도움말 본문은 `data-ux-help` 영역에 작성한다. [새 페이지 구성 예시](../accessory_planner.html)
2. 홈 카드와 상단 메뉴에 새 페이지를 연결한다. `site_nav.js`의 `SiteNavigation`에 분류, 메뉴 이름과 설명, 아이콘을 등록하고, `NEW`를 표시하는 출시 페이지에는 출시일을 등록한다. [홈](../index.html), [공통 헤더](../site_header.js), [메뉴와 아이콘 설정](../site_nav.js)
3. 공용 파일에서 해당 역할의 UI를 먼저 찾는다. 보스와 난이도 표시는 기존 `boss_identity.js`와 CSS를 사용한다. 새 공용 패턴이 필요하면 기존 호출 화면에서도 함께 확인하고, 한 화면의 예외는 해당 화면의 루트 클래스 안에 둔다. [보스 표시 코드](../boss_identity.js), [보스 표시 스타일](../boss_identity.css)

## 기존 화면에서 확인한 차이

홈과 메뉴로 진입하는 25개 화면의 상단 구조와 본문 배치를 확인했다. 보스 배율컷 프로토타입은 별도로 확인했다. [메뉴 분류](../site_nav.js), [기존 보스 프로토타입](../boss_cut_prototype.html)

- 홈과 메뉴로 진입하는 화면은 공통 메뉴 호스트를 사용한다. 장신구의 장비창 배치는 넓은 화면에서 유지하고, 480px 이하에서는 조작 가능한 장신구를 모아 터치할 공간을 확보한다. [장신구 맞추기](../accessory_planner.html)
- 계산기의 입력과 결과는 좌우 배치가 많고, 장신구 배치와 스타포스 로그는 상단 요약이 작업 흐름에 맞는다. 추가옵션 계산기에서는 `1추부터 5추까지` 참고표를 본문에서 펼친다. 신규 화면은 위의 화면 유형과 공통 도움말을 기본으로 삼는다. [추가옵션 계산기](../flame_calc.html), [스타포스 로그](../starforce_history.html)

## 완료 기준

- [ ] 적용한 화면 유형과 참조한 공용 컴포넌트가 명확하다. 예외가 있다면 적용 화면과 이유를 작업 요약에 적었다.
- [ ] 공개하는 새 화면이 홈 카드와 상단 메뉴에서 열리고, 제목, 아이콘, 메뉴의 현재 위치가 맞다. 검토용 프로토타입은 문서의 링크로 열린다.
- [ ] 처음 진입한 화면에서 다음 행동을 찾을 수 있고, 대표 결과와 단위와 조건을 바로 읽을 수 있다.
- [ ] 정상 흐름과 해당하는 빈 결과, 오류, 재시도, 저장 후 새로고침을 확인했다.
- [ ] 브라우저에서 1280px와 390px를 확인했다. 표나 고정 버튼이 있는 화면은 320px에서도 본문과 조작이 가려지지 않는지 확인했다.
- [ ] Tab으로 입력과 주요 행동에 접근할 수 있고, 키보드로 열기, 실행, 닫기가 가능하다.
- [ ] 버튼의 누르는 순간과 선택 상태가 구분된다. 스위치 ON/OFF, 라디오, 체크박스의 부분 선택, 드롭다운의 닫힘과 열림을 직접 확인했다.
- [ ] 본문, 보조 문구, 강조 값의 크기, 굵기, 색을 역할별 규격과 비교했다. 200% 확대에서 버튼, 안내, 앵커 대상이 가려지지 않는다.
